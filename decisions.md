# Seafarer Documents Manager — журнал решений

Журнал начат 05.11.2026. Новые записи — в конец файла.

## 2026-11-05 — зашифрованный .sdm и файл для судна
Запрос: «как сделать .sdm зашифрованным?», предложение принято («да»). Журнал: «запиши это изменение в журнал».

**Было.** `.sdm` — это `JSON.stringify` всего состояния, открытым текстом: паспорт и документы, биометрия с группой крови, ставка, фото, заметки, DP-дни. Экспорт только в Premium.

**Сделано**
- `utils/sdmCrypto.ts` — пароль, scrypt, AES-256-GCM (`@noble`, чистый JS). Тот же файл в `SDM-Web/utils/` и в ISM AI Pilot (`services/sdmCrypto.ts`); менять все три вместе (в ISM это проверяет `npm run check:sdmcrypto`).
- `components/BackupCryptoModal.tsx` (тот же файл в `SDM-Web`). Экспорт: полная копия или файл для судна; шифрование включено по умолчанию, можно отключить, тогда предупреждение. Импорт спрашивает пароль; старые открытые `.sdm` и `.json` читаются как раньше.
- Файл для судна: список разрешённых полей (данные, родственник, документы, стаж). Нет биометрии, ставки, фото, образования, заметок, DP-дней, комментариев к стажу. Отмечен `exportKind: 'vessel'`; SDM отказывается восстанавливать его, иначе он стёр бы остальные данные.
- ISM AI Pilot: импорт спрашивает пароль и открывает файл (см. его журнал).
- Зависимости: `@noble/ciphers`, `@noble/hashes` (приложение и SDM-Web), `expo-crypto` (приложение). `expo-crypto` — нативный модуль: нужна новая сборка, на iOS `pod install`.
- Переводы на 10 языков, `settings.crypto.*`, в обоих `locales`.

**Решения**
- `N = 2^14`, `r = 8`, `p = 1`. Замер на Hermes, Apple M3: 2^13 — 2,2 с, 2^14 — 4,4 с, 2^15 — 9 с; на телефоне дольше. Рекомендация для scrypt выше, поэтому минимум пароля 12 символов. N хранится в файле, позже можно повысить.
- Встроенного ключа нет: его можно извлечь из сборки. Забытый пароль не восстановить, экран об этом говорит.
- Файл не может потребовать больше 2^18, r 8, p 4: чужой файл не должен исчерпать память.

**Порядок выпуска**
Сначала ISM AI Pilot с чтением нового формата (иначе офицер не откроет файл), затем SDM. Старые версии SDM зашифрованный файл не открывают.

**Проверено**
- Файл, зашифрованный на Hermes настоящим модулем, расшифрован там же и открыт в ISM AI Pilot в Opera (неверный пароль отклонён, верный доводит до импорта, Unicode цел).
- SDM Web в Opera, тестовая сборка без Firebase в отдельной папке: короткий пароль, несовпадение, полная копия нечитаема, файл для судна, неверный и верный пароль, восстановление, отказ восстанавливать файл для судна, данные целы, открытый файл с предупреждением.
- Файл для судна из SDM Web открыт кодом ISM: лишних данных нет.
- Живой прогон нашёл ошибку: диалог не был добавлен на экран SDM Web. Исправлено.
- Android-бандл приложения собирается (`expo export`).

**Не проверено**
- На телефоне: новая сборка не делалась, экран экспорта приложения не запускался, время scrypt на реальном устройстве (диалог обещает до минуты; замерить на слабом Android до выпуска).
- SDM Desktop: не собирался, использует код SDM-Web.
- SDM Web с настоящим Firebase и входом.

**Не сделано, отдельные задачи**
- Облако: `SyncContext` пишет весь JSON открытым текстом в `users/{uid}`, шифрование файла это не закрывает.
- Текст «Ваша светлость…» в диалоге старого формата остался на русском, не трогала.

**Состояние.** Не закоммичено, ничего не выложено и не собрано для магазинов. В `SDM-Web/app.json` и `SDM-Web/package.json` уже были незакоммиченные правки пользователя (скрипты build, deploy), их не трогала.
